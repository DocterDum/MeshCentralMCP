# MeshCentralMCP

An MCP server that lets an AI assistant (Claude) troubleshoot devices managed by [MeshCentral](https://github.com/Ylianst/MeshCentral). Commands are approved one by one in the MCP client (for example Claude Code's tool prompt).

Written in Rust. Talks to MeshCentral over `wss://<server>/control.ashx`, the same channel its web UI uses, logged in with a login token. Nothing is exposed on customer PCs: they keep using their existing agent connection.

## Tools

| Tool | What it does |
|---|---|
| `mesh_list_groups` | List device groups |
| `mesh_list_devices` | List devices (filter by group, name, online) |
| `mesh_run_command` | Run a CMD / PowerShell / shell command on a device (by id) and return its output |
| `mesh_get_result` | Collect the output of a command that was still running when the wait ended |

The server sees whatever the MeshCentral account behind the login token can see. Every command is appended to `audit.jsonl`. Devices are addressed by their MeshCentral id (shown by `mesh_list_devices`), since names are not unique. If a command outlives its wait (default 60s), `mesh_run_command` returns a command id and the output can be collected later with `mesh_get_result`; pending ids are kept only while the server process is running.

## Setup

1. In MeshCentral, create a login token (My Account).
2. Copy `.env.example` to `.env` and fill it in.
3. Build: `cargo build --release` (needs Rust and, on Windows, the MSVC Build Tools).

### Claude Code / Claude desktop (stdio)

```json
{
  "mcpServers": {
    "meshcentral": {
      "command": "C:\\path\\to\\MeshCentralMCP\\target\\release\\meshcentral-mcp.exe"
    }
  }
}
```

The server reads `.env` from its working directory.

### Streamable HTTP and HTTPS

```
meshcentral-mcp --https 0.0.0.0:8808 --tls-cert cert.pem --tls-key key.pem
meshcentral-mcp --https 127.0.0.1:8808      # self-signed certificate, for testing
meshcentral-mcp --http 127.0.0.1:8808       # plain HTTP, loopback only
```

Serves `/mcp`. Clients must send `Authorization: Bearer <token>`.

- **Token:** generated by the server on first start (256 random bits) and stored in `mcp-http-token.txt` (override with `MCP_HTTP_TOKEN_FILE`). Run with `--new-token` to replace it.
- **HTTPS:** `--tls-cert` and `--tls-key` take PEM files. Without them a self-signed certificate is created in `mcp-tls/` (add extra host names with `MCP_TLS_NAMES=a.example.com,b.example.com`); clients must trust it.
- **Plain HTTP** is refused on non-loopback addresses unless `MCP_HTTP_ALLOW_REMOTE=1` (for use behind a TLS reverse proxy).
- The HTTP modes share one MeshCentral login for all callers.

A static bearer token is a stopgap, not real authentication; see the to-do below.
